## Summary

Eight items ship in four gate-able waves. Wave A is a documented-and-versioned reshape of the two stores the ROADMAP obliges us to schema first (vault memory notes, schedules) plus the hygiene that every later item leans on (one owned-device predicate, one API dependency module, the Wizard stream path and the **proxy stream path** finally checking the budget and logging spend). Wave B lands every server feature behind those schemas — `ask_user`, `remember`, `generate_image`, `/v1/schedules` with an in-process runner, standard-path OpenAI endpoints, budget/session facts. Wave C is the web: a no-op extraction of the Wizard thread first, then cards, the vault page and the session-cost pill (which lands on `/` without waiting for the shell merge), then the shell merge of `/` and `/wizard` behind one owner decision, then the schedules page. Wave D is `nvh launch` and voice, which depend on nothing but the composer mount.

Everything stays additive: no rename or retirement of an nvHive module, CLI spelling or route; `/v1/proxy/*` is permanent; `generate_portrait`, `nvh imagine`, `nvh/core/image_gen.generate_image`, `nvh voice`, `nvh/core/scheduler.py` all keep working. Python 3.11 stays. `nvh/core/atohi.py` and `tests/test_atohi_*.py` are never touched.

Four design corrections over the winner that matter most:

1. `ask_user` must be widened in **both** `_filter_tool_schemas` (chat.py:408-418†, what the model is shown) and `_split_by_whitelist` (:421-445†, what the model may call); the winner widened only the second, which would have left every whitelisted specialist unable to ask. The "one question per turn, never ask and act" invariant is **enforced in the loop**, not left to the prompt (§1).
2. The image cost ceiling cannot ride on a confirm card's `arguments` as the model wrote them (`_surfaced_call` returns confirm-class calls unchanged, chat.py:507-508†) nor on "folding tool spend into the turn" (confirm-class tools run after the turn via `POST /v1/wizard/tools/execute`). The profile name is **pinned server-side** onto the surfaced call and an unknown name is a refusal, not "no ceiling" (§3).
3. The WebUI's Wizard spend is invisible to every budget figure today: `wizard_chat_stream` never calls `engine._log_query` (the only call is in the non-stream path, chat.py:1758†). Worse, the **proxy stream path** bypasses the budget hard-stop and never records spend: `openai_stream_generator` (proxy.py:328†) and `anthropic_stream_generator` (:807†) call `provider.stream` directly (:401†, :902†) and a grep of proxy.py finds no `_check_budget` and no `_log_query`†; server.py returns the `StreamingResponse` (:6145-6152†) without the `_check_budget` the non-stream path runs. Coding tools stream by default, so aliasing that handler at `/v1/chat/completions` (item 5) would have propagated the hole. Wave A5 closes it before the alias exists.
4. Nothing unattended may mint, store or serve an approval token, and nothing unattended may ask a question nobody answers: `wizard_chat` gains an `unattended` flag that the schedule runner sets (§6).

## Principles

1. **Schema before reshape** (ROADMAP.md:44, :61, :69; CONFIGURATION.md:376-377). Wave A ships ids, versioned wrappers, readers and generated schema blocks before any feature writes a record. Wave A is an *additive on-disk change* (new header lines, a wrapper object, a collision suffix), not "zero behaviour change": the CHANGELOG says so.
2. **One store per fact.** `remember` writes vault notes through `append_vault_memory` (vault.py:974†); schedules stay in `state/schedules.json` (scheduler.py:36-40†); schedule runs are jobs under `$NVH_HOME/jobs/` (jobs.py:26-29) with a documented retention rule; conversations already carry uuid ids (models.py:35, :68). No new store (ROADMAP.md:166-170).
3. **Derive, don't type.** Schema tables are generated from `dataclasses.fields(...)` through `scripts/gen_config_doc.py`'s `BLOCKS` dict (:115†); the pinned set at tests/test_config_doc_parity.py:79† is edited to name the new blocks. The owned-device predicate moves from findings.py:166† into `PlatformFacts`. `/vault` categories come from `/v1/vault/status.directories` (vault.py:968). tests/test_agent_library.py's hand-typed `VALID_TOOLS` (:28-46†) becomes the registry's roster. The scheduled-run tool whitelist is derived from the chat module's own sets. Hand-typed external facts (`nvh launch` targets) carry a `verified_on` field and print "unverified" until a run is recorded.
4. **Side effect ⇒ click; sudo ⇒ red card** (tools.py:18-45). `remember` and `generate_image` are confirm-class; `ask_user` is confirm-class by mechanism and executes nothing. `SAFETY_CLASSES` stays `{auto, confirm, privileged}` (tests/test_wizard_tools.py:259†). Nothing unattended ever mints, persists, serves or consumes an approval token — and the runner is tested for exactly that.
5. **Honest cost.** Every envelope with `cost_usd` carries `cost_known`. A paid call with no price source is `cost_known: false`, and under a finite profile ceiling an unknown price counts as exceeding it (the only reading of "paid path only within the ceiling" that never invents a price). Local backends report `cost_usd: 0, cost_known: true` — no upstream bill, the same verdict the catalog gives Ollama rows; this is the one literal and it is documented as such. "Local only" is claimed only when every counted call went to a local provider, never because a sum is zero.
6. **`require_auth` on every new HTTP route**, two existing open routes tightened (O7). A route that an `<img>` tag must load is still authenticated; the web fetches it with headers and renders an object URL (web/lib/api.ts:170-199† already attaches `Authorization`/`X-Hive-API-Key`). The one new fact on an open route (`/v1/health` gains `bind_host` and `auth_mode`) is written into SECURITY.md and pinned by a test.
7. **The model never stores a secret and never chooses where a file lands.** `redact_secrets` (nvh/core/agent_guardrails.py:223†) runs on every `remember` body as a best-effort pattern pass; the confirm card showing the exact note is the human check. `remember` writes only under the process's `$NVH_HOME` (the rule the attachments route already states, server.py:1910-1918†). The privileged audit writer (core/tools.py:1291-1296†, category `Decisions`) is the only writer allowed to describe a privileged action, so `remember` is confined to `Wizard Memory`.
8. **Monolith ownership.** `nvh/api/server.py`, `nvh/cli/main.py`, `nvh/integrations/wizard/chat.py`, `nvh/integrations/wizard/tools.py`, `nvh/api/proxy.py`, `web/components/WizardChat.tsx` (later `chat/WizardThread.tsx`), `scripts/gen_config_doc.py` + `docs/CONFIGURATION.md`, `.github/workflows/ci.yml` have exactly one owner per wave. `CHANGELOG.md` and `docs/ROADMAP.md` are written only by the integrator at each wave gate.
9. **Never name the streaming service the guard test forbids** (tests/test_no_geforce_now_mentions.py scans every shipped surface). Hermetic tests under the autouse throwaway home (tests/conftest.py:48-110); network and subprocess patched.
10. **Green locally means green in CI.** Every wave gate runs what `ci.yml` runs — lint, the strict mypy scope, the `mcp-v1` file set, the wheel build — not only pytest (see Ordering).

## 1. Wizard `ask_user`

### Behaviour

Mid-turn the Wizard decides it needs a fact only the user has ("Which disk should hold models? (a) /mnt/nvme0 — 1.8 TB free (b) /home — 210 GB free"). The turn ends with a **question card**: question, up to six choice chips, a free-text box when `allow_free_text`, buttons **Answer** and **Skip**. The mascot shows `asking` (already: mascot.ts:243) with the bubble "the Wizard has a question for you" when every pending card is a question. Answering posts the answer as the user's next message; the request history also carries `tool_results: [{name: "ask_user", ok: true, summary: <answer ≤300>}]`, which `_history_tool_results_message` (chat.py:369-396) renders as `TOOL_RESULT ask_user: {"ok": true, "summary": "..."}`. Skipping records `ok: false, summary: "skipped by the user; not answered"`.

Why the answer travels twice: the user message is the authoritative, uncapped answer; the `tool_results` entry tells the model *which* question was answered and closes the card in history. The prompt rule says they are the same answer so the model does not double-weight or worry about truncation.

Why no in-turn wait: there is no pending-turn registry, no resume path, and `wizard_chat_stream` is a plain generator behind an endpoint with no request correlation (server.py:2138-2166). The card protocol is the only pause the turn has, it already carries outcomes across turns, and it is forward-compatible with a later in-turn wait (same card, same `tool_results` shape). Docs say "the Wizard asks, this turn ends, your answer starts the next one".

**One question, then stop — enforced, not prompted.** Today `_execute_tool_calls` defers a confirm-class call but still sets `ran_any_auto = True` for any auto sibling that ran (chat.py:1524-1551†), so the loop takes another iteration and the model can act on an assumption and ask a *second* question; `_surface_confirm_calls` dedups by name+arguments (:539-541†), so two differently worded questions would both become cards. The rule in B1: when `ask_user` is among a turn's deferred calls, the turn **stops iterating** (treated like `not ran_any_auto`), only the **first** `ask_user` is surfaced, and any later `ask_user` in the same turn goes to `deferred_tool_calls` with `reason: "question_pending"`. The mascot: every deferred call still yields a `tool_call` SSE event before its card (:1529†), which flips the sprite to `working` ("calling ask_user…") for the gap; B1 adds `safety_class` to the `tool_call` event and C2's `mascot.ts` ignores `tool_call` events whose class is not `auto`, so a question never shows as work. MASCOT.md gets that row.

## 2. `remember` tool + Memory filter on `/vault`

### Behaviour

"Remember that my ComfyUI lives on the second NVMe" → the Wizard calls `remember`; a confirm card **Save to your vault: "ComfyUI lives on the second NVMe"** shows the exact note (title, tags, body after redaction, "2 secrets redacted" when applicable). Run writes a vault note with a stable id, indexes just that note into the RAG `vault` collection, and the card links to `/vault?id=<id>`, which scrolls to and highlights the note. `/vault` gains a note list: category chips derived from the server, tag chips, free-text search, a **Memory** toggle (records only — `schema` of `nvh-memory/1` or `legacy`, never seeded `doc` notes), and a Forget button that removes the file and its RAG chunks. The Wizard's prompt vault block finally reports a real `memory_files` count. REPL `/remember`, `/forget`, `/memories` keep working.

### Privacy rules (binding)

1. The tool takes **exactly** `{title, body, tags}` and drops every other key before the write. The file's convention of forwarding a model-supplied `home_dir` (`_tool_rag_ask_vault` reads `args.get("home_dir")`, tools.py:390†; `VaultMemoryRequest.home_dir`, server.py:1425-1433†; `append_vault_memory` → `init_vault(home_dir)`, vault.py:983†, which creates and seeds a vault anywhere) is **not** followed: `remember` always writes to the process home, and so does `index_vault_note` when called from the tool. The tool stores only what the model composed from the conversation: `title ≤120` collapsed to one line, `body ≤2000` (tool cap; the API keeps 20000), `tags ≤8`, category fixed to `Wizard Memory`. Other categories are user/API-only; `Decisions` in particular is where the privileged audit writer lands (core/tools.py:1291-1296†) and a model-composed note must never masquerade as an audit record.
2. `redact_secrets` runs on title and body before the write; the result carries `redacted: int`. This is **best-effort pattern redaction**: `_SECRET_PATTERNS` (agent_guardrails.py:186-213†) match sk-/pk-/api_key, GitHub, PyPI, Bearer, AWS, PEM and `KEY=value` shapes but today not NVIDIA `nvapi-…`, Groq `gsk_…` or Hugging Face `hf_…` keys — the very providers `save_provider_key` handles — nor a password typed in prose. A3 adds the three prefixes; the **confirm card showing the exact note is the human check**, and the docs say so. A body that is entirely a secret (fewer than 8 non-marker characters remain) is refused: "nothing to remember after redacting secrets".
3. Exact-literal guards only: the handler refuses bodies containing `approval_token` or the `PRIVILEGED_SUDO_NOTE` string. The word "sudo" is allowed ("ComfyUI needs sudo for the udev rule" is a legitimate memory).
4. User control: every record is visible and deletable on `/vault`, from the REPL (`/forget`), the CLI (`nvh vault forget <id>`) and `DELETE /v1/vault/notes/{id}`. There is no model-callable `forget`.
5. Nothing leaves the device by remembering: notes are local Markdown; embeddings are computed by the local RAG embedder. The design does **not** inject remembered notes into every system prompt in 0.46 (that block would travel to whatever cloud provider a turn routes to); recall stays the autofold (chat.py:197-232) and `rag_ask_vault`. A shared `build_memory_context()` with a local-only guard is the 0.47 question.

### Who gets the tool

`remember` is added to the general Wizard (`tools_allowed: null`) and to **`daily-notes-coach` only** (agent-library.json:649-651 region), with one sentence added to its prompt ("When the user asks you to keep something, use `remember`; the card shows them the note before it is saved."). It is **not** added to `vault-gardener` ("never claim to have changed a file yourself", :652†) or `zettelkasten-clerk` ("Hand back the drafted notes for the user to save; you draft, they file", :690†) — their prompts forbid filing, and a model holding a filing tool while told "they file" would either violate its prompt or refuse its tool. Nor to the built-in `vault-rag` profile (profiles.py:236-252): `strict-tools`, "answers strictly from your vault". The rule is now applied consistently: a write tool goes only where the persona writes.

## 3. `generate_image`

### Behaviour

"Make me a hero image for the lab wiki" → a confirm card whose plan line reads **NVIDIA-hosted (sdxl-turbo) · cost unknown · billed to your NVIDIA account** or **local ComfyUI on :8188 · $0 · uses GPU memory while it runs**. Run → the image renders inline in the card (fetched with auth, rendered as an object URL), saved under `$NVH_HOME/outputs/images/<conversation_id or "wizard">/`, and the card result names the path ("saved to …; nvHive does not prune this folder"). Under a profile with `max_cost_usd_per_turn` the paid backend is refused server-side: "This profile has a $0.05/turn ceiling and the NVIDIA-hosted image price is not known, so nvHive used local ComfyUI" — or, if ComfyUI is not reachable, the card result says that plus "start ComfyUI (Setup → ComfyUI) or run without a specialist". With no backend at all the plan line says so before Run and Run returns the existing four-bullet hint (comfyui.py:1002-1008). The Create-Agent "Generate Portrait" button keeps working.

### Precedence and cost

`NVAPI_KEY` set → NVIDIA-hosted (decision 20, PLAN_2026-10.md:202); else local ComfyUI at its **recorded runtime host/port** from `detect_comfyui()` (comfyui.py:414-425) rather than the default-port probe (fixing :997-1001); else unavailable. The model may pass `backend: "local"` when the user says "on this box". Unifying `NVAPI_KEY` with the NIM provider's `NVIDIA_API_KEY`/`NIM_API_KEY` is **not** done by default (O2): it would silently move every Spark owner who set a free-tier NIM chat key onto the paid hosted image path ahead of their running ComfyUI.

Cost: NVIDIA image → `cost_usd: None, cost_known: False` (no catalog row, no hand-typed price); ComfyUI → `cost_usd: 0, cost_known: True` (Principle 5). Ceiling rule: a finite `max_cost_usd_per_turn` on the active profile + `cost_known: False` ⇒ the paid backend is skipped. Stated plainly: ROADMAP.md:62's "within the profile cost ceiling" is implemented as "never when a ceiling is set and the price is unknown", and with no ceiling the hosted path runs from a confirm card that says "cost unknown". Confirm-class spend never enters the LLM turn's `total_cost_usd` (chat.py:1764†, :2152†) because confirm tools run after the turn; no folding is added.

### Enforcement: the profile is pinned, not asked

The previous draft put `profile?: str` in the model-visible parameters and derived the ceiling from it. Revised:

- `profile` is **removed from the model-visible schema** of `generate_image`.

## 6. Durable schedules

### Behaviour

Schedules survive restarts, run inside the API process (WebUI-only users get them), appear on `/schedules` (list, add with the existing `30m|1h|1d` syntax, enable/disable, run now, delete, last status, last cost as a three-state pill — `null` cost on a never-run schedule shows nothing, not "cost unknown" — and a run log) and under `GET /v1/schedules`. Each run is a job (`kind: "schedule-run"`) under `$NVH_HOME/jobs/`, visible through `/v1/jobs` and `watchInstallJob` unchanged, and a Wizard turn appended to one conversation per schedule, so results show in the sidebar like any chat. `mode: ask` runs an **unattended** Wizard turn (`wizard_chat(prompt, profile=…, conversation_id=…, unattended=True, tools_allowed=SCHEDULE_AUTO_TOOLS)`) with the Wizard's own ceiling and a fixed read-only tool roster; confirm/privileged calls the model requests are recorded as `deferred` on the run **without a plan or a token** and never executed. `mode: convene` calls `engine.run_council` (today a silent no-op, main.py:11440-11458). `mode: do` is **refused by the API runner** (O5): a failed job with "mode 'do' runs tools unattended and cannot show an approval card; use mode ask (the Wizard runs safe tools on its own) or `nvh schedule start` in a terminal"; the CLI runner keeps today's behaviour with a printed warning. A run that raises records `last_status: "error"` and never claims completion (today `mark_completed` runs on error, main.py:11467-11469). `nvh schedule add|list|remove|start` keep their spellings.

### Unattended turns (Principle 4 applied)

Two hazards the previous draft left open. (1) `_surfaced_call` calls `registry.execute(confirmed=False)` for every privileged call (chat.py:510-512†), which mints a live 15-minute token through `issue_approval` (core/tools.py:171-189†) into `pending_confirm`; the `done` envelope's `tool_calls` carries those tokens (only `_persist_wizard_turn` strips them via `_persistable_calls`, :544-554†). A job `complete` payload copying `tool_calls` would have written tokens to `$NVH_HOME/jobs/<id>.jsonl` and served them from `GET /v1/jobs/{id}/events`. (2) `ask_user` would be offered to a model nobody answers; with no history between runs it would ask again every interval, paying a completion each time.

Rule: `wizard_chat` (chat.py:1635-1644†) gains `unattended: bool = False`. When set: `DIALOGUE_TOOLS` are dropped from both filters (§1); `_surfaced_call` skips `execute(confirmed=False)` and records a privileged call as `{name, arguments, privileged: True, unattended: True}` with no plan and no token; the effective whitelist is the profile's `tools_allowed ∩ SCHEDULE_AUTO_TOOLS` (or `SCHEDULE_AUTO_TOOLS` when the profile has `null`). `SCHEDULE_AUTO_TOOLS` is **derived** in chat.py: `(WIZARD_CORE_AUTO_TOOLS - LOCAL_PROBE_INVALIDATING_TOOLS) | {"web_search", "rag_ask", "system_settings_get", "system_settings_plan", "playbook_list", "playbook_plan"}` — `WIZARD_CORE_AUTO_TOOLS` (:156-158†) contains `refresh_models`, which is also in `LOCAL_PROBE_INVALIDATING_TOOLS` (:184†, with `repair_workspace`), so the subtraction is what keeps daemon restarts and workspace rewrites out of a timer. The runner passes every surfaced call through `_persistable_calls` before writing a job event (belt and braces). The roster is shown on the `/schedules` add form (from `GET /v1/schedules` → `runner.tools`) and in CONFIGURATION.md's `schedule-record` prose.

## 8. Voice in the WebUI

### Behaviour

A **hold-to-talk mic** in the composer (Wizard mode first; shared after item 4). Release → the transcript is **inserted into the textarea, never auto-sent** (a privileged request must still be reviewed and clicked). A **Read aloud** toggle uses the browser's `speechSynthesis` (zero server work, offline, works on Windows on Arm). STT is local-first: `faster-whisper` (CPU int8, default `small.en`) when `nvhive[voice]` is installed and the model is downloaded; else Groq Whisper when a Groq key exists (pill `cost unknown` — no catalog row); else the button is disabled with "Voice needs `pip install 'nvhive[voice]'` or a Groq key (`nvh advisor add groq`)". The status line under the mic names the active path and whether it costs anything, and offers **Download model (~480 MB)** when the local path is installed but the weights are not. Audio is never stored. The mic is hidden without a secure context (localhost qualifies; a LAN `--host` over http shows "voice needs https or localhost"). The browser records — no Python audio-capture path is needed, which is also the only RTX Spark story.

### Dependencies (honest)

## Schemas

### A. Memory record — `nvh-memory/1`

**Path:** `$NVH_HOME/vault/<Category>/<YYYY-MM-DDTHHMMSSZ0000>-<slug>[-<id8>].md` (`storage_layout().home / "vault"`, vault.py:107; the timestamp is `_now()` with `:` removed and `+` → `Z`, vault.py:991†; `Category ∈ VAULT_DIRS` :24-34; `-<id8>` only when the path already exists). One Markdown file per record; the file is the record; the folder tree is the store (Obsidian-readable, RAG-indexable).

**Format (exact):**
```
# {title — one line; internal newlines collapsed to spaces}

Id: {uuid4 hex, 32 chars}
Schema: nvh-memory/1
Created: {ISO-8601 seconds, UTC, +00:00}
Category: {Category}
Tags: {#tag ... | none}
Source: {wizard|repl|web|api|import|audit}

{body}
```
Meta lines are `Key: value`, one per line; readers ignore unknown keys. `parse_vault_note` keeps the blank-line partition of `_parse_memory_note` (repl.py:82-94†), so pre-0.46 notes parse identically. Every `Source:` value is produced by a real writer: `wizard` (the tool), `repl` (`/remember`), `web` (`/save`), `api` (`POST /v1/vault/memory` default), `import` (`import_legacy_memories`, repl.py:152†), `audit` (core/tools.py:1291-1296† from B1).

**Fields** (`MemoryRecord` dataclass in vault.py; CONFIGURATION.md block `memory-record` generated from `fields()` + `metadata["doc"]`; the header layout itself is one prose paragraph beside the generated table):

| field | type | notes |
|---|---|---|
| `id` | str | `uuid4().hex`; for notes without `Id:` derived as `sha1(relative_path)[:32]` — stable while the file is not moved; `nvh vault upgrade --add-ids` writes this same derived id |
| `schema` | str | `nvh-memory/1`, or `legacy` (pre-0.46 `append_vault_memory` note), or `doc` (seeded YAML-frontmatter note; not a record) |
| `title` | str ≤120 | first `# ` line, single line |
| `created` | str | ISO-8601 UTC |
| `category` | str | one of `VAULT_DIRS` |
| `tags` | list[str] | lower-case slugs |
| `source` | str | `api` when absent; see the writer table above |
| `body` | str | everything after the header |
| `path` | str | absolute path; not serialised into the file |

**Migration:** none in place; legacy files keep their names and bodies; readers derive ids. `init_vault` never rewrites user notes. `nvh vault upgrade --add-ids` is explicit and idempotent: inserts the three header lines, keeps the body byte-for-byte, refuses `doc` notes. Pre-0.42 `state/memory/memories.json` stays a one-shot import (repl.py:152-205†).

**Later import:** walk `vault/**/*.md`, `parse_vault_note`; `nvh-memory/1` ⇒ trust `Id`; `legacy` ⇒ derived id by the documented formula; `doc` ⇒ skip or import as documentation. RAG chunks are derived, not imported (re-ingest).

### B. Schedule record — `nvh-schedules/2`

**Path:** unchanged `$NVH_HOME/state/schedules.json` (`default_schedule_file()`, scheduler.py:36-40†; pinned by tests/test_storage_layout.py:493-496, :565). Lock: `$NVH_HOME/state/scheduler.lock`.

**File format v2:**
```json
{"schema": "nvh-schedules/2", "updated_at": "<ISO>", "schedules": [ {record}, ... ]}
```
**Read-compat:** a bare JSON array (today's shape, scheduler.py:58-65†) is accepted, each element defaulted, and the file is rewritten as v2 on the next save. Unknown record keys round-trip in `extra`. A parse failure quarantines the file as `schedules.json.corrupt-<ts>` and logs once.

**Write:** `json.dumps(..., indent=2, sort_keys=True)` to `schedules.json.tmp` then `os.replace` (pattern jobs.py:47-52), retried a bounded number of times on `PermissionError` (Windows: destination open in another process).

| field | type | default | notes |
|---|---|---|---|
| `id` | str | — | new: `uuid4().hex` (32); legacy 8-char ids kept verbatim |

| `interval_seconds` | int | — | `parse_interval` syntax `30m|1h|1d` |
| `advisor` | str | `""` | provider override, empty = route |
| `mode` | str | `"ask"` | `ask|convene|do`; `do` is CLI-runner only |
| `last_run` | str | `""` | ISO-8601 UTC |

| `enabled` | bool | `True` | |
| `created_at` | str | — | ISO-8601 UTC |
| `name` | str | `""` | display label (new) |
| `profile` | str | `""` | agent profile; its `max_cost_usd_per_turn` caps a run through the Wizard turn; its whitelist is intersected with `SCHEDULE_AUTO_TOOLS` (new) |
| `conversation_id` | str | `""` | the one thread all runs append to (new) |
| `updated_at` | str | `""` | (new) |
| `last_status` | str | `""` | `ok|error|skipped|deferred` (new) |

**Runs** are job records `$NVH_HOME/jobs/<YYYYmmddHHMMSS>-<8hex>.json` + `.jsonl` with `kind: "schedule-run"` and `request.schedule_id` (keys jobs.py:68-84; directory documented CONFIGURATION.md:399†). **Retention:** the runner keeps the last `SCHEDULE_RUN_HISTORY = 20` runs per schedule and prunes older pairs after `mark_run`; `deferred` entries in a run's `complete` payload never carry `plan`, `approval_token` or `approval_expires_at`.

## Risks

1. **Additive on-disk change to vault notes** (three header lines; collision suffix; one-line titles). Globs on the old filename pattern still match (the suffix appears only on collision); Obsidian users see new header lines. Mitigation: `parse_vault_note` accepts both shapes; old files are never rewritten unless `nvh vault upgrade --add-ids` is run.
2. **Schedules loader no longer swallows errors.** A hand-edited broken file is quarantined instead of silently emptied — better, and called out in CHANGELOG.
3. **Lifespan scheduler.** The lock covers `--reload` and dual `nvh serve`; a crash while holding it delays runs up to `3 × poll_s` after an unclean restart (heartbeat is the only staleness rule, so there is no pid probe to go wrong on Windows); in-flight runs are marked `interrupted` with schedule-aware wording. Tests default `NVH_SCHEDULER=0`; one lifespan test runs with it on.
4. **`do` refused under the API** (O5). CLI users lose nothing; WebUI users see a clear failed job and a hint. `ask` runs under a fixed read-only roster, so a timer can never repair the workspace or restart a daemon.
5. **Auth tightening on `/v1/anthropic/messages` and `/v1/integrations/scan`** (O7) breaks keyed deployments that relied on the open route until they send the key — Security note and `nvh launch` snippets show the token.
6. **History/tools forwarding changes `/v1/proxy/chat/completions` semantics** for existing callers (O12). Opt-out header, `Changed` entry, pinned shapes unchanged, smoke set unchanged. **Streamed proxy calls now hit `budget.hard_stop`** — a client that streamed past the budget yesterday gets a `budget_exceeded` chunk today; `Changed` entry.
7. **`imagine` → confirm** changes `nvh do`, the REPL and `/v1/smart`. The core registry runs with `enforce_confirmation=False` (core/tools.py:782†, :942†), so the class matters only where a caller checks it: `nvh do` and the REPL **prompt**; `/v1/smart` calls `run_agent_loop` with no `confirm_unsafe` (server.py:3765-3771†) and agent_loop.py:569-576† then answers "Tool requires approval: imagine" — a **refusal**, not a prompt. `detect_action` has no `imagine` mapping. Intended; O3; the test pins the `/v1/smart` behaviour.
8. **Shell merge is the largest web diff**; it is split (C1a/C1b), gated on O9, and `/wizard` redirects for one release with every inbound link rewritten in the same wave.
9. **Image ceiling enforcement pins the profile server-side**; a user who edits the card's arguments on their own machine is spending their own key, which the HMAC tier does not exist to prevent. Documented. An unknown profile is a refusal, so a stale client's direct POST never runs the paid path by accident.
10. **faster-whisper** adds CTranslate2 and a first-run model download (~150 MB `base`, ~480 MB `small.en` — approximate, re-measured at pin time) that is now explicit and off the event loop; no win_arm64 wheels, hence the environment marker; opt-in extra, never in `all`; the status endpoint reports honestly and Groq/browser paths remain; the arm64 CI step is informational.
11. **`nvh launch` targets are external facts** nvHive cannot verify from the repo; every row ships with `verified_on: null` and prints "unverified" until a maintainer records a run. `codex`'s Responses-API default and Claude Code's `tool_use` requirement are the two known reasons an env-only launch would not work, hence snippet/MCP kinds for them.
12. **Legacy vault ids are path-derived**; moving a legacy note in Obsidian changes its id until `nvh vault upgrade --add-ids` writes it. Recommended before any Atohi import.
13. **Over-asking.** One question per turn is enforced in the loop; the rule line discourages asking at all; persisted meta lets us measure after the wave; a per-conversation cap is a 0.47 follow-up if needed.
14. **Session spend is machine-wide** (CLI, other tabs, proxy clients, scheduled runs). The pill's wording says so; subtracting schedule-run costs is a follow-up if it misleads.
15. **Two CONFIGURATION.md owners per wave would collide**; the plan gives one (A3, B5) and routes every other fixer's rows through them. The same rule holds for `ci.yml` (D2 then D1) and SECURITY.md (one commit per owner).
16. **Generated images accumulate** under `outputs/images/` with no cap in 0.46. Stated in the `outputs/` row, the Tools prose and the card; `nvh outputs clean` is the 0.47 follow-up.
17. **Schedule runs accumulate** as job files; bounded to 20 per schedule by the runner, and the Setup page excludes them. A user who wants a longer log reads the schedule's conversation, which keeps every turn.
18. **`/v1/health` discloses `bind_host` and `auth_mode`** on an open route. `/v1/proxy/health` is already open and `nvh launch` needs the fact before it has a token; SECURITY.md states it and a test pins the keys.

**Considered and rejected** (review findings not applied as proposed, with the reason):

- Removing the 0.42 `/query`/`/council` redirects in 0.46 (overdue "Remove in 0.43"). Rejected: retiring routes is outside this loop's remit under the 2026-09-16 no-retirements decision; they are re-dated to retire with `/wizard` in 0.47 and the CHANGELOG says so.
